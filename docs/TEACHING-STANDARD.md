# QA Academy: стандарт учебного материала

## Язык и аудитория
Обучение Junior QA / Java Automation. Объяснения преподавателя — на русском; техническая терминология, постановка вопроса и образец ответа — также на английском. Цель — понимать задачу и объяснять решение, а не заучивать перевод.

Не утверждать, что авторские задания являются вопросами конкретного работодателя в Израиле. Не гарантировать покрытие всех собеседований. Термины и сложность брать из технических первоисточников, требования вакансий сверять отдельно.

## Обязательная структура задания
1. English question с естественной технической формулировкой.
2. Точный русский перевод и достаточный контекст: данные, ограничения, диалект или контракт.
3. Английские варианты ответа с переводом. Код не переводится. Для SQL результат проверяется на показанных данных.
4. После ответа — верный результат, содержательная часть выбранного варианта и точная ошибка. Не выдумывать, что ученик думал или понял по одному клику.
5. Пошаговое объяснение на русском с сохранением терминов.
6. Sample answer — компактный технически корректный ответ на английском и перевод без смены смысла.
7. Key terms — 3–5 нужных терминов; один новый пример на закрепление.

Expected Result — ожидаемый результат; Actual Result — фактический результат; Steps to Reproduce — шаги воспроизведения; Severity — влияние дефекта; Priority — срочность/очередность исправления. Это требования к оформлению соответствующих будущих тем, а не заявление, что эти темы уже подключены к экрану SQL.

## Оценивание
Выбор одного варианта — 0 или 5, без выдуманных частичных баллов. Разбор может отмечать верную часть варианта; это не AI-оценка развёрнутой речи. Подсказки сохраняются отдельно. Перевод не является подсказкой по SQL: его состояние фиксируется отдельно. Примеры после разбора не повышают самостоятельный результат.

Не удалять true / false, boolean, null и другие необходимые технические понятия из соответствующих уроков Java/SQL. Сначала объяснять их смысл: «условие выполняется / не выполняется», не заменять разбор ученика фразой «ложь». NULL и трёхзначная логика требуют отдельного контекста.

## Интерфейс
Не помещать в учебный экран служебные заявления «прототип», «не готовая платформа», «нет выдуманной статистики» или отчёты о разработке. Статус готовности и ограничения — в README и документации. Операционные ошибки загрузки/сохранения показывать: скрывать потерю прогресса нельзя. Не изображать официальную сертификацию или несуществующую готовность.

Проверять английский и русский варианты на одинаковый смысл, ответы и границы — на техническую корректность. Проверки структуры не заменяют редактуру содержания.
