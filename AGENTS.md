# QA Academy — правила разработки

## GitHub: обязательная проверка перед записью
- Единственный разрешённый аккаунт для записей: `VYCHESLAV1988`.
- Единственный разрешённый репозиторий: `VYCHESLAV1988/QA-Academy-`.
- Перед любым push, commit через API или изменением ветки проверять аккаунт активного подключения. Для GitHub connector: `get_user_login`; для GitHub CLI: `gh api user --jq .login`.
- Если аккаунт отличается или проверить его нельзя, ОСТАНОВИТЬ запись. Не использовать запасной токен, аккаунт, бота или чужой репозиторий.
- Проверять remote перед push. Не использовать force push. После записи проверять commit author/committer и новую вершину ветки.
- Локальный `git user.name` сам по себе не подтверждает аккаунт аутентификации.
- Эти правила для разработчика НЕ являются серверным запретом GitHub для других участников. Изменение прав доступа или rulesets требует отдельной настройки.

## Учебное направление
- Персональное обучение на русском: восстановление Junior QA Manual + Automation.
- Язык учебных заданий — **Java, НЕ JavaScript**.
- Автоматизация: Java, Selenium, JUnit Jupiter/TestNG, REST Assured, Maven.
- JavaScript в интерфейсе допустим как техническая реализация, но курс JavaScript не добавлять.
- Темы: Manual QA, тест-дизайн, API/Postman, SQL, Java, автоматизация, Git/CI, ISTQB CTFL.

## Как учить
Объяснение → пример → один вопрос → проверка → разбор → повторение → контроль.
Не заменять обучение сплошным экзаменом. Сохранять историю и прогресс в SQLite.
Отличать самостоятельные ответы, ответы с подсказкой и самооценку по эталону.
Не оценивать свободные ответы только по ключевым словам. Не выдавать самооценку за AI-проверку.
SQL проверять исполнением на изолированной учебной базе; запрещать изменение данных и файловые операции.
Не выполнять произвольный Java-код пользователя на сервере без отдельно проверенной песочницы.

## Банк вопросов
- Авторские тренировочные вопросы с объяснением и источником темы.
- Не обещать все вопросы всех собеседований и не выдавать вопросы за закрытые билеты ISTQB.
- Версию программы и источники перепроверять перед обновлением.
- Идентификаторы стабильны; существующий прогресс не ломать.
- Не заполнять банк бессмысленными дубликатами ради количества.

## Проверки и выпуск
1. Запустить автоматические тесты банка, оценивания, SQL и HTTP API.
2. Проверить вход, ответ, повторение, статистику и выход в браузере.
3. Проверить мобильный экран, контраст, читаемость, клавиатуру.
4. Обновить README и отчёт: отдельно выполненные и невыполненные проверки.
5. Выдать полный архив. Не коммитить базу пользователей, ответы, cookies, токены, секреты, экспорт прогресса и кэш.
